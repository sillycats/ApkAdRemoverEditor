✨ विशेषताएँ

🛡 सिग्नेचर बायपास (v3.0 में नया)

  • MT Manager-शैली KillerApplication इंजेक्शन: 12 इनर क्लासों वाली एक हुक क्लास को एक स्वतंत्र DEX के रूप में इंजेक्ट करता है, लक्षित Application की पैरेंट क्लास को फिर से लिखता है, और रनटाइम पर रिफ्लेक्शन के माध्यम से PackageInfo.CREATOR को मूल सिग्नेचर से भर देता है, अधिकांश Java-स्तरीय सिग्नेचर जाँचों को कवर करता है
  • ड्युअल-मोड बायपास: नॉर्मल (Java जाँचों को कवर करने के लिए हुक इंजेक्ट करना) / ओरिजिनल-मोड (नेटिव-स्तर की डिस्क पुनः-पठन सिग्नेचर जाँचों को कवर करने के लिए अतिरिक्त रूप से origin.apk + नेटिव लाइब्रेरी एम्बेड करना)
  • स्मार्ट SO इंजेक्शन: लक्षित APK के ABI का स्वतः पता लगाता है, केवल मौजूदा निर्देशिकाओं में लिखता है (arm64-v8a / armeabi-v7a आदि); यदि कोई lib निर्देशिका न हो तो सभी आर्किटेक्चर (x86 / x86_64 सहित) में लिखता है
  • अनुकूलन योग्य हुक क्लास नाम: KillerApplication का नाम स्वतंत्र रूप से बदला जा सकता है, सिग्नेचर डिटेक्शन से बचने के लिए 12 इनर क्लासों का नाम dexlib2 के माध्यम से स्वतः बदल दिया जाता है
  • पूर्णतः अनुकूलन योग्य इंजेक्शन पैरामीटर: ओरिजिनल पथ / एक्सट्रैक्ट पथ / so नाम / हुक क्लास / सिग्नेचर जानकारी / एंट्री नाम; खाली होने पर वास्तविक मान स्वतः पढ़ता है
  • व्यावसायिक (बिज़नेस) मेथड्स को कभी नहीं छूता: "चेक मेथड्स को नल-आउट करने" के विपरीत, कोई नाज़ुक कीवर्ड/फ़िंगरप्रिंट अनुमान नहीं, बाइटकोड नलिंग से स्टार्टअप-फ़्रीज़ नहीं, MT Manager जैसी ही मजबूती
  • क्रैश गार्ड: हुक DEX इंजेक्शन और Application पैरेंट रीराइट दोनों में बैकअप + परमाणु (एटॉमिक) राइट-बैक + स्वचालित पुनर्प्राप्ति का उपयोग होता है

🛡 विज्ञापन हटाने का मुख्य भाग

  • विज्ञापन सुविधाओं की 18 श्रेणियाँ: SDK लाइब्रेरीज़ / परमिशन्स / क्लासेज़ / मेथड्स / रिसोर्सेज़ / URL / Views / Activities / Services / Receivers, रीसेट सहित पूर्णतः अनुकूलन योग्य
  • गहरी AXML प्रोसेसिंग: विज्ञापन कंपोनेंट्स और विज्ञापन परमिशन घोषणाओं को हटाता है, Res-लो रेआउट के विज्ञापन Views को छिपाता है
  • मेथड-स्तरीय परिशुद्धता: विज्ञापन-क्लास के मेथड्स को नल-आउट करता है, विज्ञापन लिंक को खाली करता है, View ज्योमेट्री को खाली करता है
  • VIP अनलॉक: विज्ञापन निर्णयों को बायपास करने और मेंबरशिप अनलॉक करने के लिए जबरन true/false लौटाता है
  • विज्ञापन रिसोर्स सफाई: विज्ञापन SDK नेटिव लाइब्रेरीज़ (.so), एसेट्स के विज्ञापन रिसोर्सेज़ और रूट के विज्ञापन फ़ाइलों को स्वतः साफ़ करता है
  • Flutter समर्थन: Dart AOT स्नैपशॉट को पार्स करता है, libapp.so में विज्ञापन स्ट्रिंग सिग्नेचर मिटा देता है

📦 आकार अनुकूलन

  • डेटा पुनः-उपयोग अनुकूलन: बायपास पैक (जैसे LSPatch आर्टिफैक्ट्स) मूल डेटा सेक्शन का पुनः उपयोग करते हैं, जिससे आकार लगभग ~50% तक कम हो जाता है
  • नाम बदले गए APK की पहचान: बिना एक्सटेंशन या मनमाने एक्सटेंशन वाले नाम बदले गए मूल पैक्स को सटीक रूप से पहचानता है
  • DEX आकार अनुकूलन: डीबग जानकारी (लाइन नंबर / लोकल वेरिएबल टेबल) हटाता है, आगे 5%~15% तक छोटा
  • स्मार्ट कम्प्रेशन + ZIP अलाइनमेंट: सुनिश्चित करता है कि दोबारा पैक किया गया APK सामान्य रूप से इंस्टॉल हो और चले

🔒 स्थिरता और सुरक्षा

  • v1 + v2 ड्युअल साइनिंग, कम-वर्ज़न डिवाइसों के साथ संगत, परिणाम सीधे इंस्टॉल होते हैं
  • DEX क्रैश गार्ड: बैकअप सुरक्षा + परमाणु लेखन + स्वचालित पुनर्प्राप्ति

  • कम-मेमोरी स्कैनिंग: बिना फ़्रीज़ हुए विशाल DEX को स्थिर रूप से संभालता है

बिल्ड

# आवश्यकताएँ: Android Studio / JDK 17+ / SDK 34
./gradlew assembleRelease

आउटपुट app/build/outputs/apk/release/ पर मिलता है, सीधे इंस्टॉल योग्य।

इस प्रोजेक्ट में GitHub Actions ऑटो-बिल्ड है: प्रत्येक push/PR पर Debug और Release कंपाइल होते हैं; v* टैग प्रकाशित करने पर APK आर्टिफैक्ट्स के साथ Release स्वतः जारी होता है।

रिलीज़ नोट्स release-drafter द्वारा स्वचालित रूप से उत्पन्न होते हैं: शीर्षक/शाखा/परिवर्तित फ़ाइलों (feature/bug/docs/ci आदि) के आधार पर PR को स्वतः टैग करता है, और रिलीज़ पर संरचित चेंजलॉग का सारांश देता है।

उपयोग

  1. प्रोसेस करने हेतु APK चुनें (नाम बदले गए APK समर्थित हैं)
  2. "प्रोसेसिंग प्रारंभ करें" पर टैप करें: स्वतः अनपैक, विज्ञापन हटाना, आकार अनुकूलन, दोबारा पैक, साइन
  3. मूल निर्देशिका में स्वतः निर्यात होता है, Markdown प्रोसेसिंग रिपोर्ट उत्पन्न करता है
